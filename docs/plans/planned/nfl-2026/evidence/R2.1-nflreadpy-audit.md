The R2 wave packet requires an nflreadpy currency/capability audit with typed
freshness and failure metadata. Direct R1 evidence in

## Delivered contract

- `ProviderCapabilities` records provider name, supported datasets, current-
  season support, and the source-license note.
- `FreshnessMetadata` records requested and available seasons, an aware UTC
  retrieval timestamp, and `complete`/`partial`/`empty` status.
- `FailureMetadata` records typed unavailable/error classification, exception
  type, safe message text, and optional season.
- `LoadResult` retains the existing `data` and `skipped_years` fields while
  carrying the typed metadata. Normalization preserves metadata.
- nflreadpy responses now identify missing seasons even when a multi-season
  response is partial, and retain typed unavailable failures.

## Diagnosis packet — blocked after repeated review repairs

Status: Blocked after authorized follow-up review

The authorized follow-up still leaves core acceptance failures. The previous
completion claims below are superseded by this diagnosis; no further repair is
authorized under the current repair-loop threshold.

### Exact remaining reproductions

1. With `readpy.nfl = None`, `NFLReadPyProvider.load_weekly([2025])` enters
   `_require_nflreadpy()` and raises the raw `ImportError`; that path is outside
   `_fetch_with_fallback`, so it produces neither `FailureMetadata` nor a
   `LoadResult`.
2. The legacy `_safe_load` does not infer `skipped_years` from an empty frame or
   from a multi-season frame missing one requested season. Empty legacy data is
   therefore reported with incomplete semantics, and partial legacy data can
   report `skipped_years=[]`.
3. `tests/testdata/nflreadpy_provider_shape.json` is committed but unused by
   regression tests and has no immutable manifest/hash assertion in the test
   contract. The fixture therefore does not prove the advertised provider
   shape.
4. The provider capability mapping is still noncanonical: source-facing
   aliases and canonical dataset labels are mixed between `datasets` and
   `audit`, so consumers cannot derive one stable dataset key from the
   advertised matrix.
5. `_fetch_with_fallback` duplicates HTTP/error classification in the bulk
   request and per-season retry branches. The duplicated logic can classify the
   same failure differently and is not a single typed error contract.

### Root causes

- The initial contract modeled 404/skipped seasons but not typed non-404
  failures or provider-level failures.
- Capability parity was added as static metadata without a shared helper that
  normalizes every provider's success and failure responses.
- Fixture provenance and post-commit evidence sequencing were not specified
  before implementation, so tests cannot prove reproducibility independently
  of monkeypatched loader behavior.
