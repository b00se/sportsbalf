## Contract

`src/nfl/data/identity.py` provides a deterministic, offline identity graph
for players, teams, and games. Every mapping is keyed by explicit Underdog ID
and positive season. Resolution returns typed `resolved`, `unresolved`, or
`ambiguous` outcomes. Names are retained as diagnostics only and cannot
resolve a record. Missing identifiers, invalid seasons, season mismatches,
and one UD ID mapping to multiple GSIS IDs fail closed. The material-player
report is suitable for an export gate and is ready only when every requested
player resolves exactly once.

`tests/testdata/nfl_identity_graph_fixture.json` with SHA-256

## Final diagnosis after repair attempt two

Status: Blocked after two materially similar repair reviews

The implementation is not accepted as a complete R2.2 packet. The following
acceptance blockers remain and must not be papered over by weakening tests:

- The export gate is an optional keyword on `export_rankings_csv`, not a
  dedicated non-bypassable unattended-export entrypoint. There is no proof
  that every unattended output path invokes identity validation, nor a
  no-write regression proving that a blocked export leaves its destination
  untouched.
- Material-row key selection is not fully specified or observable. The current
  first-present alias policy must be documented and tested for all supported
  keys (`appearance_id`, `ud_player_id`, `nflverse_id`, `consensus_id`, `id`,
  and `playerId`), including conflicting aliases. A valid appearance record
  can be mis-selected when another alias is present.
- Time/trade selection is not observable in the result: player resolution does
  not expose the selected team or the source row used. The implementation does
  not prove that a traded player returns the correct team at the requested
  date/game, and overlapping validity windows are not rejected or surfaced as
  ambiguous.
- Week scoping accepts string/int equivalence but does not normalize and
  validate week values as one typed contract. Mixed representations and
  malformed weeks need explicit tests and typed failures.
- The frozen fixture and tests do not cover explicit `ud_team_id` and
  `ud_game_id` rows, despite the new ingestion aliases.
- Evidence is not self-contained: the repair commit hash and independent
  Luna-high review result are still pending. The RED claim for attempt two is
  historical implementation intent rather than a recorded pre-change test
  output.

## Final diagnosis after scoped-reset repair attempt two

Status: Blocked after two materially similar repair attempts

The scoped identity model is directionally correct, but R2.2 is not accepted.
The remaining blockers are contract-level and must be repaired without weakening
the fail-closed export gate:

- A canonical `nflverse_id` lookup can still merge rows carrying different team
  contexts. Canonical identity must remain one player while the selected team
  context is either explicitly scoped or surfaced as ambiguous; it must never
  silently choose or merge teams.
- Overlapping validity intervals with the same team are not rejected or
  surfaced. Identical-team overlaps can hide duplicate source records and must
  fail ingestion or resolve ambiguously.
- Week validation accepts values that should be rejected by the typed contract,
  including booleans and fractional values that happen to coerce through
  `int()`.
- A row containing only `gsis_id` can still be treated as canonical. The
  contract requires an explicit `nflverse_id`; GSIS is a mapped external field,
  not a substitute canonical identity.
- Fixture-backed tests/evidence still need explicit team/game alias coverage,
  malformed-week coverage, and a regression proving an existing destination's
  bytes remain unchanged for unresolved or wrong-scope material rows.
