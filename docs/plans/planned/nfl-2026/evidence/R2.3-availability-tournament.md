# R2.3 Availability Source Tournament

Status: Implemented pending independent review (strict table-derived gate)

The offline availability contract accepts deterministic observations from
Underdog, Sleeper, ESPN, and public roster/depth data. Each observation carries
canonical `nflverse_id`, source, normalized status, confidence, UTC observation
time, freshness, and provenance. Source acquisition remains optional; fixture
loading is network-free and hash-auditable.

Reconciliation uses explicit source weights and confidence-adjusted voting.
Fresh or explicitly valid observations are retained as reportable decisions.
Disagreement is retained as a warning and marks a conflict. The unattended gate
fails closed for missing fresh data and for unknown/conflicting high-impact
players; non-impact conflicts remain reportable without blocking.

## Superseded diagnosis after two availability-gate repairs

Status: Superseded by the strict table-derived gate below

The source tournament and basic fail-closed behavior are implemented, but the
unattended availability gate is not yet authoritative enough to accept:

- The caller supplies `availability_player_ids` independently of the rankings
  table. A caller can therefore omit a material canonical player from the
  availability set and still pass the gate. The production boundary must derive
  material canonical IDs from the export table through the accepted R2.2
  identity graph, then require exact (or explicitly documented equivalent)
  decision coverage.
- `availability_as_of_utc` is optional at the export boundary. The gate must
  require an explicit `datetime` value that is timezone-aware; omitted values,
  strings, naive datetimes, and integer timestamps must all fail closed. Every
  decision must carry the same typed timestamp (and requested season).
- The current test proving a blocked export uses a manually supplied canonical
  ID set and a decision whose metadata is constructed directly. It does not
  prove table-derived material coverage or rejection of omitted/string/naive/
  integer `availability_as_of_utc` values.

Exact reproductions:

```python
export_unattended_rankings_csv(
    table, destination, identity_graph=graph, season=2026,
    availability_decisions={"p1": decision},
    availability_player_ids=("p1",),
    high_impact_players=("p1",),
)
```

This succeeds even when `table` contains another material row resolving to
`nflverse_id="p2"`. It also succeeds when `availability_as_of_utc` is omitted,
because the current implementation only compares it when non-`None`.

## Strict table-derived gate acceptance proof

The R2.3 cleanup packet derives the material canonical player set at the
unattended export boundary, after resolving rankings rows through the accepted
R2.2 identity graph. An explicit `is_material` row flag takes precedence; when
absent, the deterministic default is `adp <= 50` (overrideable with
`material_rank_cutoff`). Availability decisions must exactly cover that set;
caller-supplied IDs are retained only as a compatibility assertion and cannot
narrow the derived set. Every export requires a real timezone-aware
`availability_as_of_utc`, and every decision must carry the same timestamp and
requested season. All validation occurs before opening the destination.
