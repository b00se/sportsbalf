# R2.4 Projection/Consensus Source Audit

Status: Superseded by the accepted R2.4 scorer closeout; retained as audit history.

## Contract

`src/fantasy/adapters/nfl/projection_sources.py` is an offline-only audit
contract. Each candidate must declare a zero cost, license name and URL,
commercial-use and redistribution permissions, a versioned snapshot format,
an approved reproducible retrieval method, a UTC source timestamp, and a
lowercase SHA-256 digest. Missing or disallowed values fail closed. Freshness
is measured against an explicit UTC `as_of_utc` and configurable maximum age;
future timestamps and stale snapshots are ineligible.

The tournament ranks eligible candidates deterministically by descending
coverage score, then freshest snapshot, then source ID. It never fetches or
scrapes a URL. Archived bytes and the digest are therefore the reproducibility
boundary. The default configuration is recorded in
`config/fantasy/nfl_projection_sources_2026.yaml`.

The checked-in survey records two credible independent baselines: nflverse
(CC BY-SA 4.0, eligible public projection baseline) and FantasyPros consensus
(free to view but non-commercial/non-redistributable under its terms, retained
as a rejected consensus reference). Promotion therefore requires one licensed
public baseline plus an independent consensus reference whose terms pass the
same gates; no source is promoted merely because it is popular.

Historical evaluation consumes archived rows with `player_id`, `game_id`,
`season`, `week`, `projection`, and `actual` columns. Evaluation is a
rolling-origin comparison by season/week against (1) a historical player
mean and (2) the public baseline; consensus is scored only when its snapshot
timestamp is at or before the week cutoff. Coverage is the fraction of
material slate players with a resolved ID and non-null projection. Every
snapshot records source URL, license evidence URL, version, retrieval cadence
(weekly), UTC freshness timestamp, schema/format, and SHA-256 digest.

## Final diagnosis — scorer repair blocked after two similar reviews

No further code change is authorized in this packet. Independent reviews
continue to identify the following unresolved acceptance failures:

- First-row baseline/denominator semantics are not fully specified: a target
  row without prior history is skipped while coverage and MAE denominators are
  computed over different effective populations. This makes the first scored
  week and baseline comparison ambiguous.
- Independence needs separate enforcement and evidence for both normalized
  publisher lineage and registrable domain lineage; role names alone are not a
  sufficient proof of independent public and consensus baselines.
- Material-player coverage must normalize resolved IDs, exclude blank IDs,
  reject nonnumeric projections, deduplicate players, and use one explicit
  denominator. The current fixture-backed assertions do not cover all of
  these combinations.
- Raw malformed season/week values and malformed evaluation timestamps can
  escape the intended typed failure envelope during ordering/cutoff logic.
- Regression tests are missing for first-row denominator behavior, separate
  baseline timestamp cutoffs, publisher/domain cross-collisions, malformed
  season/week fields, malformed target timestamps, and mixed blank/duplicate
  material IDs.

### Reproductions and review evidence

- Focused command: `.venv\\Scripts\\pytest.exe -q tests/fantasy/adapters/nfl/test_projection_sources.py`
  passed `9`; this does not exercise the missing cases above.
- Full command: `.venv\\Scripts\\pytest.exe -q` passed `419`; no existing
  suite test supplies malformed season/week or target-cutoff fields.
- The scorer currently requires baseline keys but reads evaluation-side
  historical/baseline columns in addition to separate files, so a fixture can
  pass without proving that the separate baseline values are the scored values.
- Coverage is derived after row filtering and is not independently asserted
  against a mixed duplicate/blank/non-numeric material-player fixture.

### Narrow follow-up boundary

The next packet must be limited to scorer contract/test repair: define the
first-row policy and denominators, score only separate baseline fixture values,
normalize publisher/domain lineage independently, validate all season/week and
timestamp fields into `SourceAuditError`, and add the listed regression
fixtures. It must not alter source licensing policy, identity mapping, feature
store work, protected directories, or begin R2.5. Human review should approve
the exact denominator and first-row policy before implementation resumes.

- `load_projection_sources("config/fantasy/nfl_projection_sources_2026.yaml")`
  parses metadata, but the registry contains documentation URLs and synthetic
  digest values rather than archived source bytes. Re-running a tournament
  cannot reproduce the claimed projections from this checkout.
- The original evidence named pre-amend commit `fb282f0`; the repair evidence
  similarly named pre-amend `1e2cf13`. The accurate final repair commit is the
  hash above. This demonstrates the root cause of the commit-evidence failure:
  embedding a commit hash inside a subsequently amended commit necessarily
  makes that embedded hash stale.

### Root-cause hypotheses

1. The loader validates declarations but has no archive/artifact resolver, so
   “loadable config” is confused with “reproducible source input.”
2. `content_sha256` is accepted as metadata without checking bytes from a
   local snapshot; the checked-in hashes are placeholders, not evidence.
3. `run_projection_source_tournament` returns eligible declarations but does
   not require two independent eligible baselines or an evaluation fixture.
4. API-level failures are represented only by in-memory audit results; malformed
   config and missing snapshot artifacts need a stable failure envelope for
   unattended callers.
5. Commit hashes cannot be made self-consistent by amend-in-place evidence;
   the foreman must record the final hash externally or use a post-commit
   evidence update policy.

### Unresolved acceptance criteria

- Two independent free, licensed baseline archives with real bytes, verified
  license terms, and reproducible digests are unavailable in the repository.
- Historical evaluation fixtures and a runnable rolling-origin scorer are not
  implemented by R2.4; only the schema/contract is documented.
- Material-player identity resolution and coverage measurement are not wired
  into this audit.
- No stable API failure record exists for missing archives, invalid licenses,
  or insufficient baseline count.

### Recommended next decision / authority

Stop R2 at the human gate. Obtain operator approval for (a) the exact two
source licenses and redistribution rights, (b) permission to add immutable
source snapshot fixtures under an approved non-protected directory, and (c) a
post-commit evidence convention that records the final commit without an
amendment cycle. Then assign one narrowly scoped follow-up packet to implement
archive-backed verification and the two-baseline historical scorer. Do not
advance to R2.5 until those artifacts and gates are independently reviewed.

## Final diagnosis — repair loop exhausted

Status: Blocked pending a new narrowly scoped packet.

The independent final review identified materially similar baseline and lineage
validation gaps after two scorer repairs. No further production change is made
in this packet.

### Reproductions

- Calling `score_rolling_origin_snapshot(target)` without explicit
  `public_path` or `consensus_path` aliases the target snapshot for both
  baselines. A target-only fixture can therefore appear to have two separate
  baselines, violating the separate-source contract.
- A source with an invalid or unknown hostname can normalize to an empty or
  unusable registrable-domain token. The tournament must fail closed on that
  metadata instead of allowing a lineage comparison to proceed.
- The current focused suite passes (`19` tests) and the full offline suite
  passes (`438` tests), but neither suite proves omitted baseline paths fail
  closed or invalid/unknown domains are rejected.

### Narrow next-packet boundary

The next packet must be limited to projection scorer/source validation:

1. Require explicit, distinct public and consensus baseline paths (or expose a
   typed opt-in that makes the aliasing behavior impossible); never silently
   use the target path as a baseline.
2. Validate canonical publisher-family and registrable-domain tokens as
   non-empty, domain-like values and reject unknown/invalid domains with
   `SourceAuditError`.
3. Add offline regressions for omitted baseline paths, target-only fixtures,
   malformed hostnames, and unknown domains.

Do not alter provider code, licensing policy, identity mapping, feature-store
work, protected directories, or begin R2.5. Because this is the second
materially similar repair failure, stop for foreman/human review after the
diagnosis packet.
