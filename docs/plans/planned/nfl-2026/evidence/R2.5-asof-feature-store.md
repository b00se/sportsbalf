# R2.5 As-of feature store

Status: Accepted; user-approved timestamp-gated simplification.

The deterministic `AsOfFeatureStore` accepts target rows keyed by canonical
`nflverse_id` and an explicit timezone-aware `as_of_utc` cutoff. Normalized
provider, projection, availability, or identity-derived evidence is eligible
only when its source timestamp is at or before that row's cutoff. Optional
event/game/slate columns scope a match, and each selected value retains source
timestamp, provenance, and freshness seconds. Missing/naive timestamps,
unresolved canonical IDs, missing provenance, duplicate source observations,
and required-but-unavailable evidence fail closed.

Acceptance tests include same-player future projection perturbation, future
availability/source-row perturbation, strict timestamp validation, and
unresolved-identity rejection. Future rows cannot alter historical output.

## User-approved simplification — timestamp gate, optional hash

The personal-project contract does not require a cryptographic digest to build
features.  A supplied `SnapshotEvidence` now requires source identity,
timezone-aware retrieval time, and an exact row count; it defensively copies
the input table when it is created.  A SHA-256 may still be recorded as audit
metadata, but it is not a production gate.

The leakage gate remains strict: every source row must have a timezone-aware
`source_timestamp_utc` at or before the target `as_of_utc` (normally kickoff),
and target-game rows are excluded.  Empty source sets still fail.  Duplicated
canonical observations, blank game/event/slate identifiers, and conflicting
latest categorical observations fail closed.  A Week-1 player with no own
history can only receive a prior-season/global numeric fallback from a valid
supplied snapshot; no evidence-free fallback exists.

### Exact reviewer reproductions

1. The public signature still exposes `require_evidence=False`. Calling
   `build_nfl_feature_store(targets, {}, require_evidence=False)` bypasses the
   required source-set gate (or can return target-shaped output in the no-source
   branch). Production callers must have no bypass; if a test-only escape hatch
   is retained, it must be private and unexported.

2. Build a source containing two rows with the same
   `(nflverse_id, game_id, source_timestamp_utc)` and different feature values.
   The builder accepts both rows and averages numeric values / takes the last
   categorical value. Duplicate canonical observations must fail closed.

3. Provide two source tables with eligible rows at the same timestamp for one
   target, then reverse the source mapping insertion order. Numeric results can
   change through averaging and categorical results can change through
   `values[-1]`. Selection must be globally deterministic across sources with
   an explicit source-name/tie-break rule; no result may depend on input order.

4. Construct `SnapshotEvidence(frame, valid_hash, ...)`, mutate `frame` after
   construction, and call the builder. The build path does not revalidate the
   digest and the mutable frame remains the source of inference. Evidence must
   be copied/immutable at construction or build time and its hash checked again
   immediately before selection.

5. Add a target or source row with `game_id=""` (and analogous blank
   `event_id`/`slate_id`). Source blanks are checked, but target scope is not
   rejected. Any scoped target with a blank scope must fail closed rather than
   silently becoming an unscoped join.

6. Week-1 fallback must be allowed only from snapshot-backed, hash-verified
   prior-season or hierarchical/global evidence. It must emit explicit fallback
   and missingness flags. If no eligible prior/global evidence exists, required
   inference still fails closed; fallback must not become an evidence bypass.

## Repair attempt 2 — reviewer P1 closure

Snapshot evidence now requires a lowercase 64-character SHA-256 matching the
canonical CSV serialization (or an explicitly pinned manifest digest). Blank
provenance and blank scoped game/event/slate values fail closed. Production
construction always requires nonempty evidence; there is no opt-out path.
Source rows are sorted by timestamp before selection, and target-game rows are
excluded. The adapter is exported from `src.fantasy.adapters.nfl`.

The output includes deterministic per-feature missingness and fallback flags,
plus a JSON missingness summary and season. When a player has no current prior,
numeric features use prior-season values where available and then a global
hierarchical prior. Future perturbation tests compare model features while
allowing the expected snapshot hash change.
