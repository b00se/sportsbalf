# R2.6 Projection-Source Fixture Line Endings

Status: Implemented.

## Root cause

The declared digests match the canonical Git blobs, which use LF line endings.
On Windows, the working-tree checkout converted these CSV fixtures to CRLF,
so the verifier hashed different raw bytes and rejected both snapshots. The
verifier and declared SHA values remain unchanged.

## Repair

`.gitattributes` now enforces `text eol=lf` for exactly these fixture paths:

- `tests/testdata/fantasy/nfl/projections/nflverse_week01.csv`
- `tests/testdata/fantasy/nfl/projections/consensus_week01.csv`

Canonical Git-blob SHA-256 values:

- `nflverse_week01.csv`: `3cc634e802d868801a77b6cc94fa2b72a5a19191fbe39b168328fe0d66707e59`
- `consensus_week01.csv`: `8bd8020c36edb7298b1d61a2c56bf0ef389ded1e73c585cdb393d557af1be0c1`

## Verification

- Focused tests: `.venv\\Scripts\\pytest.exe -q tests/fantasy/adapters/nfl/test_projection_sources.py` — passed.
- Ruff: `.venv\\Scripts\\ruff.exe check .` — passed.
- Whitespace: `git diff --check` — passed.
- `git ls-files --eol` for both paths reports index LF, working-tree LF, and
  `attr/text eol=lf` after targeted normalization.

## Follow-up coverage

The same canonical-LF rule now also covers the availability and identity JSON
fixtures plus the `nflreadpy_*.csv` provider fixtures. Their manifests already
contained the correct Git-blob hashes; no hash, schema, test, or verifier logic
was changed. The combined availability, identity, and provider fixture suite
passes with all covered files reporting working-tree LF.
