# R3.10-A archive adapter

Status: Implemented; R3.9 and R4 remain blocked pending real baseline inputs

`src/nfl/data/archive.py` provides an offline-safe boundary for dataframes
returned by the existing `nflreadpy`/`nfl_data_py` providers. It writes a
deterministic CSV payload and a sibling JSON manifest to a caller-supplied
cache path (which may be outside the repository). The manifest records source
URL and version, retrieval UTC, requested/available seasons, explicit cutoff
semantics, row count, byte size, SHA-256, provider package version, and a
deterministic schema fingerprint.

Payload and manifest creation use exclusive-create semantics. Loading verifies
the manifest shape, UTC timestamp, payload size and digest, parsed row count,
and schema fingerprint before returning a dataframe; malformed or tampered
artifacts fail closed with `ArchiveIntegrityError`.

Offline evidence:

```text
.venv\\Scripts\\pytest.exe -q tests/test_nfl_archive.py
7 passed
.venv\\Scripts\\ruff.exe check src/nfl/data/archive.py tests/test_nfl_archive.py
All checks passed
```

The adapter establishes immutable archive capability but does not acquire
network data, clean/materialize features, or supply Underdog/consensus
baselines. Therefore the R3.9 acceptance gate and R4 decision remain blocked
until qualifying timestamped multi-season inputs are available.
