# R3.11-B Archived Baseline Runner

Status: Blocked; not approved after final independent review.

## Scope

`src/nfl/models/archived_baseline_runner.py` provides a deterministic runner
from an nflverse weekly provider response (or an existing immutable archive)
to canonical half-PPR player-week outcomes and both weekly expanding-origin
and season-held-out baseline evaluations. It accepts an injected provider for
offline tests, verifies archive manifests on reads, and requires callers to
provide an external cache directory. It filters to QB/RB/WR/TE and rejects
duplicate player-week identities before archival and before scoring.

No repository `data/` files were created or modified.


This packet did not run that network command. The resulting weekly and season
statuses remain subject to archive coverage and the R3 multi-week gate; no R4
promotion is implied. The runner rejects partial provider coverage, malformed
numeric statistics, invalid calendars, and protected repository output/cache
paths. When `output_dir` is supplied it writes `outcomes.csv`, weekly and
season metrics CSVs, and a sorted `run_manifest.json` for evidence capture.
The output manifest records the archive payload and manifest paths and SHA-256
digests, each output digest, requested seasons, fetch mode, scoring path,

canonical columns must agree; fumble components (including sacks) and distinct
conversion components are summed without double counting. An injected
provider's optional `load_weekly_raw` frame is checked for duplicate identities
before its normalized `LoadResult` can reconcile/deduplicate rows.

## Final diagnosis (2026-09-11)

The final independent review found three residual issues. Per orchestration
rules, no code repair is being attempted in this task.

1. **P1 — predictions are not persisted.** `run_archived_baseline_backtest`
   returns prediction frames in memory through the two evaluator results, but
   the output bundle persists only `outcomes.csv` and metrics (`src/nfl/models/
   archived_baseline_runner.py:259-261`). A rerun cannot audit the exact
   predictions used for the reported metrics. This blocks the reproducibility
   and evidence requirement until weekly and season prediction CSVs (and their
   digests) are persisted.

2. **P2 — configured-provider raw duplicate guarantee is unavailable.** The
   pre-reconcile check uses optional `load_weekly_raw` at
   `src/nfl/models/archived_baseline_runner.py:207-212`; the configured
   providers expose only `load_weekly`. Their common reconciliation path calls
   `drop_duplicates` at `src/nfl/data/providers/base.py:88-95` before the
   runner sees the frame. Reproduction with seven source rows containing one
   exact duplicate yields six rows after `reconcile_seasons`, so the runner
   cannot prove the original seven-row identity set. This remains a data
   integrity gap, not a reason to weaken duplicate rejection.

3. **P2 — provider/package provenance is wrong.** Fetch mode records the
   provider name as `source_version` at
   `src/nfl/models/archived_baseline_runner.py:227`, and records the `pip`
   distribution version as `runner_package` at line 297. Neither is the
   configured nflverse provider package/version. The archive manifest must
   identify the actual provider distribution and version (for example,
   `nflreadpy`) before a real archive run can be accepted.

### Gate impact and boundaries

R3.11-B is blocked/not approved. R3 cannot close and R4 remains blocked: no
real archive run occurred, and the current evidence cannot establish complete
prediction persistence, source-row duplicate provenance, or correct provider
version provenance. The next task requires an explicit implementation packet
for these three findings, followed by independent review and a real external
cache run. It must not expand into R4, historical Underdog reconstruction, or
profitability claims. A human decision is required on whether the configured
provider API should be extended to expose pre-reconcile raw frames or whether
the provider must emit a source-row manifest before normalization.
