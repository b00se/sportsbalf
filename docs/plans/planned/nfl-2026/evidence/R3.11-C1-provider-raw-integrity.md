# R3.11-C1 provider raw integrity

Status: Implemented; R3.9 and R4 remain blocked

## Scope

The configured `nflreadpy` and legacy `nfl_data_py` adapters now implement the
`NFLDataProvider.load_weekly_raw` contract. This path returns the provider's
weekly source rows before `reconcile_seasons` and therefore preserves exact
duplicate player-week rows for archive identity validation. It fails closed
when the response lacks season provenance, cannot be fetched, or does not cover
every requested season. Existing `load_weekly` behavior remains compatible.

Both providers also expose source and adapter package provenance through
`ProviderProvenance` and `ProviderCapabilities.provenance`.

## Evidence

Offline regressions in `tests/test_nfl_provider_metadata.py` prove that:

- configured-style `nflreadpy` and `nfl_data_py` stubs retain exact duplicate
  player-week rows through `load_weekly_raw`, while normal loading reconciles
  identical rows;
- missing season coverage raises `RawSourceUnavailableError`; and
- provider capabilities expose the same typed provenance object.
