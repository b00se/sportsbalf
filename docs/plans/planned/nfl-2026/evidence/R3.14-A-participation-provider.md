# R3.14-A strict nflverse participation provider

Status: Implemented; downstream component adapter and R4 remain blocked

## Scope

`NFLReadPyProvider` now exposes the configured `nflreadpy.load_participation`
surface through `load_participation` and `load_participation_raw`. The real
source is play-level (2016-present), with `nflverse_game_id`, `play_id`, player
list fields, and categorical route information; it is not a player-week route
count table. The loader derives only season/week from the encoded game ID,
normalizes play identity (including season 2016-present, week 1-22, and finite
integer play IDs), and retains every source column and duplicate source
row. It never fabricates numeric `routes`, targets, or player IDs.

Any numeric player-week route consumer must remain fail-closed until a separate
validated aggregation is implemented.

The legacy `nfl_data_py` provider has no reliable participation equivalent. Its
normal method returns one typed `UnsupportedCapability` failure per requested
season, and its strict method raises `UnsupportedCapabilityError`; it never
fabricates route data or silently falls back to a different dataset.

## Final-review diagnosis (P2; no further repair in this packet)

The provider remains unapproved because the calendar upper bound is computed
at import time in `src/nfl/data/providers/readpy.py`:

```python
_PARTICIPATION_MAX_SEASON = datetime.now(UTC).year + 1
```

That permits a syntactically valid one-season-ahead game ID even when the
nflverse participation archive does not yet publish that season. For example,
when the runtime year is 2026, a fixture row with
`nflverse_game_id="2027_01_DEN_OAK"` passes calendar validation and can be
reported as available if a source stub returns it. This is a reproducibility
and source-availability boundary, not evidence that the future season exists.

The 52-test, Ruff, and `git diff --check` results above remain valid for the
implemented contract, but do not clear this residual P2. The provider is
therefore unapproved; receiver route archival and the component backtest are
blocked. The direct fantasy-point baseline and tournament work are unaffected.
R4 remains blocked.

The next packet must decide between a strict current-year cap and an explicit
source-availability allowlist/metadata contract, add a regression for the
chosen policy, and obtain a fresh independent review. This diagnosis is
docs-only and intentionally makes no code change.
