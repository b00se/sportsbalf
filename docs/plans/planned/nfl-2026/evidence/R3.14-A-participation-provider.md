# R3.14-A strict nflverse participation provider

Status: Implemented; downstream component adapter and R4 remain blocked

## Scope

`NFLReadPyProvider` now exposes the configured `nflreadpy.load_participation`
surface through `load_participation` and `load_participation_raw`. The real
source is play-level (2016-present), with `nflverse_game_id`, `play_id`, player
list fields, and categorical route information; it is not a player-week route
count table. The loader derives only season/week from the encoded game ID,
normalizes play identity (including season 2016-present, week 1-22, and finite
integer play IDs), and retains every source column and duplicate source
row. It never fabricates numeric `routes`, targets, or player IDs.

Any numeric player-week route consumer must remain fail-closed until a separate
validated aggregation is implemented.

The legacy `nfl_data_py` provider has no reliable participation equivalent. Its
normal method returns one typed `UnsupportedCapability` failure per requested
season, and its strict method raises `UnsupportedCapabilityError`; it never
fabricates route data or silently falls back to a different dataset.
