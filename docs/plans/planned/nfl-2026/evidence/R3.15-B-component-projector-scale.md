# R3.15-B Component Projector Scale

Status: Implemented; awaiting independent review.

## Scope

This packet optimizes only the approved QB and RB component projectors. Each
projector now sorts and partitions normalized history once per invocation, then
passes each target only its entity history. The hot-path ratio means use NumPy
arrays instead of constructing pandas arithmetic objects for every component.
The strict prior-calendar filter, rolling window, fallback behavior, output
columns, validation, and fantasy scoring mappings are unchanged.
Historical team-share behavior is preserved exactly: each finite weekly share
is clipped to `[0, 1]` before its rolling mean (including negative and greater
than-one source ratios). A regression covers the `[2, 0]` ratio case for both
QB and RB shares.

## Measured behavior

The new deterministic acceptance test executes the full archived component
evaluation (adapter, weekly folds, QB/RB projections, fantasy scoring, and
metrics) on exactly 11,468 rows across 109 weekly folds. It requires at least
10,000 predictions and uses a broad 90-second upper bound to detect the prior
multi-minute regression without making CI host speed part of the result.

Representative local profile before the change:

```text
25 folds / 1,000 rows: 6.018 seconds
```

After the change:

```text
25 folds / 1,000 rows: 2.065 seconds
core projector/evaluation command (excluding this packet's test file): 62 passed
full focused command (including this packet's test file and scale run): 65 passed
```

The exact-scale test is the authoritative completion check and must be run in
the final review environment. No cache or future-row state is introduced.
