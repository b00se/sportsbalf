# R3.16-A — NFLverse WR/TE route derivation feasibility audit

Status: Audited; partial feasibility established, WR/TE projection gate remains blocked.

## Scope and conclusion

This packet audits the real `nflreadpy` schemas only. It does not change the
provider, archive adapter, feature materializer, or models.

NFLverse participation data is sufficient to derive a conservative numeric
**identified-receiver route-row count** per player/week. It is not sufficient
to claim that every WR/TE who appears in `offense_players` ran a route. The
participation row has one categorical `route` value, while the player lists
contain all offensive participants. The defensible linkage is therefore:

1. Join participation to PBP on (`nflverse_game_id`, `play_id`) = (`game_id`,
   `play_id`).
2. Keep regular pass plays with `play_type == "pass"` and `pass_attempt == 1`.
3. Require a non-empty categorical `route` and non-null `receiver_player_id`.
4. Require that `receiver_player_id` occurs in the semicolon-delimited
   `offense_players` list and map its aligned entry in `offense_positions`.
5. Keep only the linked receiver's WR/TE position, then count rows by receiver
   ID, season, and week.

Rows with no receiver ID, no route, a no-play, or an alignment/key failure are
excluded and reported as unavailable; they must never be assigned to all
offensive players or imputed as routes. This produces a lower-bound / identified
route measure, not a proven complete route-run measure. If the R3.4 contract
requires complete routes run, the receiver candidate remains unsupported until
NFLverse exposes an explicit route-player mapping or an equivalently documented
source.

## Reproducible source probes

Environment: `nflreadpy==0.1.3`; requested season `2023`; network was used only
to read the published source, with no repository data written. The following
read-only probe was run from the repository's `.venv` (the full one-line
command is reproducible by substituting the displayed expressions in a Python
invocation):

```text
P = nflreadpy.load_participation([2023]).to_pandas()
B = nflreadpy.load_pbp([2023]).to_pandas()
Q = P.merge(B, left_on=["nflverse_game_id", "play_id"],
            right_on=["game_id", "play_id"])
```

Observed participation schema (46,168 rows):

```text
nflverse_game_id, old_game_id, play_id, possession_team,
players_on_play, offense_players, defense_players, route,
offense_names, defense_names, offense_positions, defense_positions,
offense_numbers, defense_numbers, ...
```

Observed PBP linkage/schema (49,665 rows):

```text
game_id, play_id, season, week, play_type, pass_attempt,
complete_pass, incomplete_pass, interception, passer_player_id,
receiver_player_id, receiver_player_name, posteam, ...
```

The participation sample demonstrates that `offense_players` and
`offense_positions` are aligned semicolon-delimited lists, while `route` is a
single categorical value. For example, a pass row has receiver
`00-0037741` (Jahan Dotson), route `HITCH/CURL`, and that ID is the WR entry in
the aligned offensive lists. PBP `receiver_player_id` is the identity anchor;
participation does not provide a separate `route_player_id` column.

Exact 2023 aggregate probe output:

```text
PASS_ROUTE_ROWS 18667 receiver_linked 18189 unlinked 478 unlinked_pct 2.561
PLAYER_ROUTE_ROWS 18189
duplicate_play_keys 0
linked_positions {'WR': 10822, 'TE': 3910, 'RB': 3312, 'FB': 90,
                  'QB': 48, 'DT': 2, 'T': 2, 'CB': 1, 'ILB': 1, 'G': 1}
nonempty route counts {False: 26552, True: 19616}
```

The linked-position output is a source-quality warning: route labels also
link to RB/FB and a small number of other positions. Position filtering is
mandatory; route labels must not be treated as WR/TE-only. The 478 unlinked
pass-route rows include incomplete/unknown-receiver cases and cannot be
assigned without inventing an identity. No duplicate (`game_id`, `play_id`)
keys were observed in this season after the source join.

Roster identity was independently probed with `load_rosters_weekly([2023])`.
The roster schema uses `gsis_id` (not `player_id`) plus `season`, `week`,
`team`, `position`, and `full_name`. Example joins resolved
`00-0031260` to Logan Thomas (TE) and `00-0037741` to Jahan Dotson (WR).
Thus, if roster position is used rather than aligned participation position,
the required identity join is (`season`, `week`, `gsis_id`) and team must be
checked against PBP `posteam`.

## Temporal and gate implications

The route count is an observed weekly statistic. For an outer slate `(season,
week)`, only route rows from strictly earlier weeks may enter the feature
materialization; the target week's participation/PBP rows are scoring data and
must remain hidden. The participation source has season/week/play identity but
no finer publication timestamp, so this audit does not establish within-week
as-of availability for any live slate.

This packet establishes a viable conservative input for a separately scoped
WR/TE candidate if the feature contract names it `identified_receiver_routes`
(or equivalent) and reports coverage. It does **not** authorize relabeling it
as complete `routes`, filling missing receiver identities, or promoting a
receiver model. R3.16-A therefore leaves WR/TE component evaluation
inconclusive, and the R3 wave/R4 gate remains blocked pending either:

- an explicit acceptance of the lower-bound identified-receiver feature with
  coverage metrics and at least three untouched outer folds; or
- a source with a documented player-to-route mapping that covers all intended
  route runners.

No Underdog or consensus history was evaluated by this packet.
