# R3.16-B — identified receiver route materializer

Status: Implemented; independently reviewable; does not promote WR/TE routes.

This packet adds `src/nfl/features/receiver_routes.py`. It joins participation
to PBP on `(nflverse_game_id, play_id) = (game_id, play_id)`, retains regular
pass attempts with a nonempty categorical route and receiver identity, and
maps the receiver through aligned `offense_players`/`offense_positions` lists.
Only WR/TE rows are counted as `identified_receiver_routes` by player/season/
week/team/position. Optional weekly roster lookup is available when the aligned
position columns are absent, and checks `(season, week, team, player)`.

Rows with missing identities or failed linkage are excluded and quantified by
`ReceiverRouteDiagnostics`, including an auditable anti-join count for
participation route rows absent from PBP. No routes are imputed and the output
is never called complete routes. Duplicate or malformed play keys, route types,
season type, team values, and aligned lists raise `ReceiverRouteSchemaError`.
Season values are restricted to 1920--2100, weeks to 1--22, and integer play
IDs to 0--1,000,000. The source must explicitly provide nonempty
`season_type`; only `REG` rows are retained.

`materialize_identified_receiver_route_history(..., as_of=(season, week))`
materializes the complete conservative source and then returns only rows from
strictly earlier calendar weeks, so the target week's participation/PBP rows
cannot enter a fold. The helper does not assert within-week publication time.
