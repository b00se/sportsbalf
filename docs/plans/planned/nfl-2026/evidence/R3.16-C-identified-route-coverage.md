## Strict materialization result

The first strict call to
`materialize_identified_receiver_routes(participation, pbp)` fails with:

```text
ReceiverRouteSchemaError: pbp posteam must be a nonempty string
```

The failure is caused by 13,538/247,284 PBP rows (5.4746769%) having null
`posteam`; these are non-play/no-play rows. Among 101,870 eligible pass-attempt
rows, zero have null `posteam`, so this source defect does not affect the
candidate pass-route population. After restricting the caller frame to valid
`posteam` rows solely to quantify the candidate population, strict alignment
validation fails with:

```text
ReceiverRouteSchemaError: must be a string offense_positions alignment at row 2
```

The exact observed population is:

| Quantity | Count |
| --- | ---: |
| Participation rows with nonempty route | 94,710 |
| Unmatched participation route rows after PBP key join | 0 |
| REG pass-attempt route rows (source population) | 87,302 |
| With nonempty `receiver_player_id` | 86,088 |
| Without receiver identity | 1,214 |
| Receiver-linked rows with both alignment columns usable strings | 50,769 |
| Receiver-linked rows with missing `offense_positions` | 35,319 |
| Receiver-linked rows with length mismatch | 0 |
| Receiver-linked rows with duplicate offense players | 0 |

Therefore no WR/TE materialized frame, WR-vs-TE player-week counts, or
route-to-weekly-outcome join coverage is reported as completed. The 50,769-row
aligned count is an input-quality diagnostic only; it is not a materializer
result, because the current function fails closed on the first missing alignment
row rather than returning a partial frame.

## Required safe repair before rerun

1. Make `ArchiveAdapter` schema verification stable across provider → CSV →
   pandas round trips, with a regression test over these mixed-type snapshots.
2. Validate `posteam` only for rows eligible to become pass-route candidates (or
   explicitly permit null values on rows that cannot qualify), while retaining a
   diagnostic count. Never fill a missing team.
3. For missing `offense_positions`, use an explicitly archived weekly roster
   keyed by `(season, week, team, gsis_id)` and only accept exact WR/TE identity
   matches. Otherwise exclude the row and count it. Never infer position from
   the outcome table or impute it from another week.
4. Re-run the full 2021–2025 materialization and publish diagnostics, WR/TE
   player-week counts, and a validated join to the archived weekly outcomes.
   The rerun must remain strictly regular-season/as-of safe and must not be
   promoted or treated as R4 evidence until those counts and tests pass.

R4 remains blocked. This packet is diagnosis/evidence only; it contains no
production-code, data-directory, model, or acceptance-gate changes.
