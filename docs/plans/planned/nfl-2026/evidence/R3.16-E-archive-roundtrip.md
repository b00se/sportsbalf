# R3.16-E: Archive CSV round-trip evidence

Status: Complete for the archive adapter repair; R4 remains blocked by the
separate R3.16-D receiver-route diagnosis.

## Problem and correction

`ArchiveAdapter.write()` originally fingerprinted pandas storage dtypes, while
`load()` reads CSV values under pandas CSV inference. Mixed nullable NFLverse
columns could therefore have valid bytes, SHA-256, and row count yet fail the
schema fingerprint gate.

The adapter now fingerprints CSV-stable value semantics. It recognizes native
datetime, boolean, numeric, strict ISO-like datetime strings, and strings
without broadly parsing arbitrary text. Empty strings are treated as CSV null
fields during inference, matching `to_csv()`/`read_csv()` behavior. SHA-256,
payload size, row count, required manifest fields, and tamper failures are
unchanged.
