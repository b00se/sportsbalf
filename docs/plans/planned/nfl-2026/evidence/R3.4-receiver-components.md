# R3.4 Receiver Components Evidence

Status: complete

Implementation adds a typed, deterministic, offline-safe WR/TE projection API
for routes, targets, receptions, receiving yards/touchdowns, and rare rushing
components. History is canonicalized by `(receiver_id, position, season, week)`;
semantic duplicates, invalid positions, nonfinite values, and invalid calendar
keys fail closed, including malformed/null required statistics and supplied
opportunity caps. Source and projected touchdowns are bounded by their
receptions or rushing attempts. Every target uses only observations strictly before its
calendar boundary, optionally limited by an earlier `as_of` boundary.

## Scope

- `src/nfl/models/receiver_components.py`
- `tests/test_nfl_receiver_components.py`
- this evidence record

The API applies team pass-attempt, route, target, and rush-attempt opportunity
caps when supplied. It guarantees nonnegative outputs, routes as the route
opportunity bound, targets no greater than routes or team targets, receptions no
greater than targets, and availability probabilities in `[0, 1]`. New players
use explicit bounded priors. Rolling-origin evaluation passes identity/calendar
columns only to prediction, so target-fold opportunity fields cannot influence
the score or promotion decision; promotion requires model MAE to tie or beat
the transparent global-mean target baseline.

statistics and any supplied caps now reject coercion to null rather than
silently falling back. Historical touchdowns are rejected when they exceed
receptions or rare rushing attempts, and projected receiving/rushing

malformed stats/caps and adversarial touchdown values. Focused tests, Ruff, and
the whitespace check were rerun successfully before amending the task commit.
