# R3.5 Role Priors Evidence

Status: complete

This packet adds a typed, deterministic, offline-safe prior contract for QB,
RB, WR, and TE player-component forecast inputs. `build_role_priors` uses
strictly earlier `(season, week)` observations, recognizes only supplied
rookie/new-role context (while labeling mere absence of history as
`no_history`, never as inferred rookie status), and emits
position-aware conservative replacement priors with explicit source,
classification, history count, and widened uncertainty metadata. Optional UD
and consensus values are treated as bounded scale context; raw preseason
yards/TDs and future observations are not inferred or consumed.

## Exit-criteria mapping

1. Every no-history player receives `classification=no_history`, an explicit
   `prior_source`, and `uncertainty_multiplier > 1`; supplied `role_context`
   or boolean new-role flags similarly identify promoted/new-role players.
   Limited eligible history is separately reported with its actual count and
   `limited_player_history` source.
2. Position-specific replacement values cover QB/RB/WR/TE components. Rookie
   and new-role values shrink toward replacement and report wider uncertainty
   than established-role history.
3. Calendar keys are normalized before semantic duplicate detection. History
   eligibility is strict `< target` and strict `< as_of`; target-fold fields
   are never passed into rolling-origin projection.
4. Component, context, configuration, and external values fail closed on
   Python/NumPy booleans, malformed, nonfinite, or negative inputs. The
   documented depth-chart role set is enforced; draft year/round/capital and
   external projections are finite and bounded. Calendar validation rejects
   implausible overflow-scale seasons without platform integer overflow.
   Rookie/new-role uncertainty multipliers are required to exceed
   established-role uncertainty.
5. `rolling_origin_compare` reports model MAE, fixed position-replacement
   baseline MAE, folds, and promotes only when model MAE ties or beats the
   baseline. Its tests cover transparent promotion output and mutation-safe
   as-of behavior.

No R3.6, R3.7, or R3.8 behavior is implemented by this packet.
