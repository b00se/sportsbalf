# R3.7 Exact fantasy scoring and direct-FP benchmark

Status: complete

## Scope

This packet owns only:

- `src/nfl/models/fantasy_scoring.py`
- `tests/test_nfl_fantasy_scoring.py`
- this evidence record

The scoring transform is deterministic and offline-safe. It defaults to
standard half-PPR and accepts an explicit `full_ppr` (or compatibility `ppr`)
override. The only coefficient difference between the defaults is receptions.
Passing yards/TDs, interceptions, rushing and receiving production, lost
fumbles, and two-point conversions are accounted for exactly once. Inputs are
validated for finite nonnegative values, booleans, aliases, and mechanical
opportunity coherence.

The direct benchmark is intentionally separate from component accounting: it
uses a strictly prior trailing mean of supplied direct fantasy-point outcomes
(or observed component-derived outcomes when no direct outcome column is
available), emits `benchmark_kind=direct_fantasy_points`, and never exposes a
component breakdown. Rolling-origin folds use strict calendar keys (`< fold`)
and return comparison metrics, but `promoted` is always false. R3.8 must apply
the required nested, multi-metric, multiple-comparison-controlled selection
before any benchmark or residual can receive weight.

## Exit-criteria mapping

1. Hand-calculated QB/RB/WR/TE-compatible component fixtures cover exact
   passing, rushing, receiving, interception, fumble, and 2PT accounting.
2. Half-PPR default and explicit full-PPR differ only by the reception
   coefficient; unknown rulesets fail closed.
3. Invalid, boolean, nonfinite, negative, alias-conflicting, and incoherent
   opportunities fail closed without weakening acceptance gates.
4. The direct benchmark is distinct, strict-cutoff, target-fold isolated, and
   non-promoting absent R3.8 evidence.

No R3.8 ensemble or promotion behavior is implemented by this packet.

## Independent review repair 1

The Luna-high review identified ordering-sensitive direct benchmarks, incomplete
QB opportunity checks, implicit unseen-player fallback, and loss of rare
receiver rushing when canonical rushing columns were present at zero. The
repair sorts all calendar histories before trailing windows, enforces
`completions + interceptions <= pass_attempts` and passing TDs not exceeding
completions, marks no-history benchmark rows explicitly, reports the rolling
global-mean fallback policy, and combines distinct rare-rush opportunities
without double counting. The focused suite covers each regression.

## Independent review repair 2

The second Luna-high review identified aggregate masking of impossible
canonical or rare rushing touchdown streams and boolean calendar coercion.
Each stream now validates touchdowns against its own attempts before rare-rush
aggregation, and calendar season/week validation rejects Python and NumPy
booleans. Both adversarial cases are covered by focused regressions.

## Independent review repair 3

The third Luna-high review identified partial rare-rush streams and fragile
reception configuration coercion. Any supplied rare-rush fields now require
the complete attempts/yards/TD stream, while reception values accept supported
numeric strings and reject malformed, boolean, or nonfinite values with a
clean `ValueError`. Partial-stream and configuration regressions are covered.

## Independent review repair 4

The final targeted review identified semantic duplicate rows whose season/week
values differed only by string versus numeric representation. Benchmark and
rolling inputs now normalize calendar columns before duplicate detection, and
both benchmark and rolling duplicate regressions are covered.
