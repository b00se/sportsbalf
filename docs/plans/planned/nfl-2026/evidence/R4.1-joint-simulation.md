# R4.1: Correlated joint player outcome simulator

Status: Complete; offline simulation only. The direct-FP input remains
explicitly unpromoted and is not a production-model promotion or an
automation of drafts, uploads, or entries.

## Contract

`src.nfl.models.joint_simulation.simulate_joint_player_outcomes` accepts a
player-level `pandas.DataFrame` with `player_id`, `game_id` (or `game`),
`team`, a finite numeric `projection` (with compatibility aliases
`direct_fp_projection` and `prediction`), and direct-FP provenance. A
non-promoted status is required through `promotion_status`/`status`, unless
the provenance token itself explicitly records that status. All input columns
are retained in the long-form output, which adds `simulation_id` and
`simulated_fantasy_points`.

Each draw uses a private `numpy.random.default_rng` initialized from an
explicit seed. A zero-mean game factor and a zero-mean game/team factor are
shared by the relevant players; independent zero-mean player noise controls
the residual variance. Thus input projections remain the marginal means in
expectation, while same-game/team correlations are positive and configurable.
The simulator makes no claims about component-stat reconciliation because its
input is a direct fantasy-point projection table.

## Repair loop 1

Independent review identified two fail-closed contract gaps: contradictory
`promotion_status`/`status` aliases could previously pass validation, and
input metadata named `simulation_id` or `simulated_fantasy_points` could be
overwritten by generated output columns. The repair now requires status aliases
to agree after normalization and rejects both reserved output names before
sampling. Tests also assert the visible output attribute
`provenance_status == "direct_fantasy_points_unpromoted"`.
