# Wave R3.10 — NFLverse archive ingestion and cleaning

Status: Planned; implementation packet not started; R4 remains blocked

## Objective

Make the existing `nflreadpy` path usable as the internal historical source
for the R3.9 rolling-origin backtest. This is an ingestion/cleaning packet,
not a projection-model or ranking packet. It must produce immutable,
manifest-addressable local snapshots while preserving the existing provider
contracts and the no-lookahead boundary.

## Reusable capability already present

`src/nfl/data/providers/readpy.py` already wraps `nflreadpy` for weekly player
stats, schedules, play-by-play, and passing NGS. It converts provider objects
through `to_pandas()`, coalesces known nflverse aliases, coerces season/week
and numeric fields, filters foreign seasons, retries by season, and returns
typed `LoadResult` freshness/failure metadata. The provider intentionally
advertises only those four implemented surfaces.

`src/nfl/data/qb_attempts.py` composes weekly stats, schedules, PBP, and NGS;
its feature calls (`src/nfl/features/qb_features.py`) create prior-season/game
QB, team/opponent, NGS, and schedule-context fields. The existing builder
already maps historical team abbreviations and can write parquet. Existing
tests cover alias normalization, season reconciliation, and the provider
fixture manifest, so these are reusable foundations rather than a new loader.

## Required implementation packets (disjoint ownership)

1. **R3.10-A — archive adapter and manifest** (owner: provider/archive)

   Own only the nflreadpy fetch-to-local boundary and a manifest schema. Add
   explicit source URL/version, retrieval timestamp, requested and available
   seasons, cutoff semantics, row count, byte size, SHA-256, package version,
   and schema fingerprint. Use exclusive-create or content-addressed writes;
   never silently overwrite a snapshot. A cache hit must verify its manifest
   before use. Dependency: none beyond current provider contract.

2. **R3.10-B — cleaning and internal feature materialization** (owner:
   dataset/features)

   Own only normalized joins and feature materialization from A's verified
   snapshots. Assert unique keys, valid season/week, canonical team/player
   identity, and deterministic sorting. Fix the confirmed lookahead in
   `compute_team_and_opponent_features`: the season-wide league neutral
   pass-rate denominator is currently computed before the team rows are
   shifted, so a later week's PBP can change an earlier week's
   `pass_rate_over_expected`. Build each target week's features from rows
   strictly before its cutoff, and add a regression that perturbs a future row
   and asserts every earlier feature is unchanged. Retain raw snapshot
   references on every output. Dependency: A's manifest and normalized
   schemas. This packet is not complete until the fix and perturbation test
   pass.

3. **R3.10-C — R3.9 runner integration** (owner: backtest)

   Own only wiring the verified internal archive into the existing component,
   scoring, ranking, and metrics runner. It must fail closed when manifests,
   coverage, or as-of timestamps are absent. Dependency: A and B, plus the
   already-defined R3.9 baseline inputs. This packet does not acquire or
   reconstruct Underdog or consensus history.

Parallel work is safe between A and documentation review only. B waits for A's
schema/manifest contract; C waits for both. No packet may edit protected
`data/`, `models/`, `betslips/`, or notebook directories in the repository.
Runtime downloads may use a separately approved local cache; checked-in code
and tests remain offline-safe.

## How nflverse data enters R3

Schedules supply game identity, dates, teams, week, totals/spreads, and
division context. Weekly player stats supply observed component outcomes and
player/team/opponent keys. PBP supplies lagged QB efficiency and team/opponent
rates; NGS passing supplies the optional lagged passing metrics. These become
the historical outcome/feature side of the R3 component projections and exact
fantasy scoring. Identity and availability joins must be applied before a
slate is eligible, and the resulting rankings are downstream products of the
same fold.

NFLverse is an outcomes/statistics source. It does not prove historical
Underdog lines/projections or an independent-consensus projection history.
Those remain separately sourced, timestamped, terms-checked inputs. A current
Underdog API response or a post-hoc consensus reconstruction cannot be labeled
an as-of historical baseline.

## Acceptance and R4 gate

The packet is complete only when an immutable multi-season local archive can
rebuild at least three distinct outer weeks and R3.9 can run end to end with
fold-level manifests and metrics. Missing or unverifiable market baselines,
insufficient outer weeks, manifest mismatch, or any future-row leakage keeps
the decision **R4 blocked**. R4 becomes **allowed** only through the R3.9
acceptance gate; R3.10 alone never promotes a model.
